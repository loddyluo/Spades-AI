# 问卷回答

## 1. DMC算法是什么？其求解流程是什么？

DMC（Deep Monte-Carlo）算法是深度蒙特卡洛搜索算法，是一种结合了蒙特卡洛树搜索（MCTS）和深度学习价值评估的强化学习方法。在双明手求解器中，DMC算法用于在完全信息状态下搜索最优解。

**求解流程：**

1. **选择（Selection）**：从根节点（当前游戏状态）开始，使用树策略（如UCT公式）选择子节点，直到到达叶子节点或未完全展开的节点。

2. **扩展（Expansion）**：如果当前节点不是终止状态且未被完全展开，则扩展该节点，选择一个未探索的合法动作创建新子节点。

3. **模拟（Simulation）**：从扩展的节点开始，使用快速策略（如随机出牌）进行蒙特卡洛模拟，直到游戏结束，获得最终得分。

4. **回溯（Backpropagation）**：将模拟结果（得分）沿搜索路径回溯更新所有祖先节点的统计信息（访问次数、累计价值）。

5. **迭代**：重复以上步骤多次，最后根据根节点子节点的统计信息选择最优动作。

对于Spades双明手求解，由于游戏是团队对抗（2v2），需要优化团队总得分差（己方得分-对方得分），因此在价值评估和回溯时需要以团队为单位进行计算。

## 2. 您所写的DMC的双明手求解器中，是否涉及估值网络？您打算定义怎么样的网络用于估值？只有一个网络吗？

在Spades双明手求解器中，**不涉及深度学习估值网络**。原因如下：

1. **项目规模与目标**：本项目是教学性质，旨在让大二学生能轻松看懂代码，深度学习网络会增加复杂度。

2. **完全信息特性**：双明手求解器拥有完全信息（所有玩家手牌可见），可以使用确定性搜索算法，不需要神经网络进行局面评估。

3. **实现简化**：使用启发式评估函数替代神经网络，更易于理解、调试和验证。

**使用的评估方法：**

1. **随机模拟评估**：在叶子节点使用随机模拟完成剩余牌局，基于Spades计分规则计算最终得分差。

2. **启发式评估函数**：对于未完成的牌局，使用以下启发式指标：
   - 剩余王牌（黑桃）的数量和质量
   - 各花色控制权评估
   - 叫牌合约完成情况预估
   - 团队合作优势评估

**如果有多个网络的情况**：
由于不使用神经网络，所以不存在多个网络。但会有多个评估组件：
- 随机模拟器：用于快速评估叶子节点
- 启发式评估器：用于局面快速排序
- 缓存系统：存储已评估局面的结果

## 3. 您最终实现的求解器能实现从任何游戏局面出发，找出当前步的最优行动吗？还是说，有一定几率找错？

**求解器的准确性与局限性：**

1. **理论最优性**：在无限计算时间和资源下，深度蒙特卡洛搜索可以渐进收敛到最优解。

2. **实际限制**：受限于计算时间和资源，实际实现有以下特点：
   - **近似最优**：在有限搜索迭代内，返回当前找到的最优解
   - **概率保证**：随着搜索迭代增加，找到最优解的概率增加
   - **可能出错**：在复杂局面下，有限搜索可能导致次优选择

3. **Spades特性影响**：
   - **搜索空间**：每墩最多有13张可选牌，13墩游戏深度可控
   - **团队协作**：2v2团队博弈增加复杂度，但合作目标明确
   - **叫牌信息**：nil/blind nil叫牌提供额外约束和目标

**准确率保证：**
- 对于简单局面（剩余牌少、决策明显）：接近100%最优
- 对于中等复杂度局面：在合理时间内达到高概率（>95%）最优
- 对于极复杂局面：可能返回近似最优解，但保证优于随机或简单启发式策略

**验证方法：**
- 与穷举搜索（对小规模局面）对比验证
- 通过大量测试牌局统计胜率/得分
- 与其他已知最优策略对比

## 4. 您准备实现的求解器最终可以返回一个怎么样的数据？

求解器返回的数据结构设计如下：

### 主要返回值：

1. **最优动作**：当前玩家的最佳出牌（Card对象或动作ID）

2. **动作价值评估**：每个合法动作的价值评估信息
   ```python
   {
       "best_action": Card("S", "A"),  # 最佳出牌
       "action_values": [               # 所有合法动作的评估
           {
               "action": Card("S", "A"),
               "value": 15.7,          # 预期得分差（己方-对方）
               "visits": 1250,         # 搜索访问次数
               "confidence": 0.92      # 置信度/胜率估计
           },
           # ... 其他动作
       ],
       "state_evaluation": {           # 当前局面整体评估
           "expected_score_diff": 12.3,  # 预期最终得分差
           "team_win_probability": 0.87, # 团队获胜概率
           "certainty": 0.75            # 评估确定性
       },
       "search_statistics": {          # 搜索过程统计
           "iterations": 10000,
           "time_elapsed": 2.45,       # 秒
           "nodes_expanded": 3521,
           "cache_hits": 1284
       }
   }
   ```

### 不同调用模式下的返回：

1. **实时决策模式**：返回最优动作及简要评估
2. **分析模式**：返回完整的动作价值分布和局面分析
3. **批量求解模式**：返回多个局面的最优策略序列

### 数据用途：

1. **AI决策**：直接用于AI玩家出牌
2. **局面分析**：用于教学、解释AI决策
3. **性能评估**：用于算法优化和调试
4. **训练数据**：可用于生成监督学习数据（如果需要）

### 与项目框架集成：

返回的数据结构将兼容现有的`AIPlayer`接口，可以通过包装器将求解器集成到现有的游戏循环中，同时也可以作为独立工具用于局面分析和研究。
